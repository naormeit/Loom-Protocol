# ATP Specification v1

ATP, the Agent Transfer Protocol, is a request-response contract for safely reserving finite resources on behalf of autonomous agents.

## Handshake Endpoint

`POST /v1/handshake`

## Packet Fields

Required:

- `agent_id`: unique identifier for the requesting agent.
- `intent`: natural-language description of the desired transaction.
- `intent_hash`: stable resource identifier or hash of the resource-specific intent.
- `expiry`: lock expiry in milliseconds.

Optional for signed mode:

- `nonce`: unique value generated by the client.
- `timestamp`: Unix timestamp in seconds.
- `signature`: HMAC-SHA256 signature over the canonical packet fields.

## Canonical Signing Fields

The MVP signs these fields:

- `agent_id`
- `intent`
- `intent_hash`
- `expiry`
- `nonce`
- `timestamp`

Fields are serialized as compact JSON with sorted keys before signing.

## Responses

### 201 Locked

The resource lock was secured.

```json
{
  "status": 201,
  "message": "Atomic Lock Secured.",
  "correlation_id": "example",
  "parsed_as": "PURCHASE ONE LIMITED ITEM"
}
```

### 409 Conflict

The resource is already locked. The agent should use the negotiation payload to retry, back off, or choose an alternative.

```json
{
  "status": 409,
  "message": "Conflict Rejected: Resource currently locked by AGENT-A.",
  "correlation_id": "example",
  "conflict_with": "AGENT-A",
  "negotiation_payload": {
    "action": "RENEGOTIATE",
    "suggested_alternative_resource": "DROP-001_ALT",
    "retry_backoff_ms": 250
  }
}
```

### 403 Unsafe Intent

The intent failed the safety screen and no lock was attempted.

### 401 Authority Failure

The packet failed signature, freshness, nonce, or authority checks.

### 400 Invalid Packet

The packet is malformed or missing required fields.

## MVP Guarantees

- The local ledger allows only one active lock per `intent_hash`.
- Unsafe intent is rejected before the ledger is mutated.
- Signed mode rejects missing signatures, invalid signatures, stale timestamps, and replayed nonces.

## Out Of Scope For v1 MVP

- Payment settlement.
- Vendor checkout execution.
- Legal identity proof without Entra integration.
- Global multi-region consistency until Cosmos DB mode is implemented.
